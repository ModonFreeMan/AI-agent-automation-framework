# 5. 质量验证层

## 适用任务

证明代码变更满足需求，并尽量没有引入回归。

## 先读文件

- `layers/02-project-knowledge.md`
- `layers/03-dev-environment.md`
- 项目测试配置和 CI 配置。

## Agent 应做

- 根据风险选择验证范围。
- 优先运行与变更最相关的测试。
- 对共享模块、核心流程和安全逻辑扩大验证范围。
- 明确说明未能运行的测试和原因。

## Agent 不应做

- 声称未运行的测试已经通过。
- 只做静态阅读就断言行为正确。
- 为了通过测试删除关键断言。

## 输入

- 需求或缺陷描述。
- 修改文件列表。
- 测试命令。
- 质量门禁规则。

## 输出

- 测试结果。
- 静态检查结果。
- 手动验证步骤。
- 剩余风险。

## 完成标准

Agent 能给出可复现的验证证据，或清楚说明为什么暂时无法验证。
